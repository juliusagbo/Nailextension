================================================================================
                                1. OVERVIEW
================================================================================

The Nailed by Via database is designed to support a comprehensive appointment
scheduling system for a nail salon business. The system handles customer
management, service catalog, appointment booking, favorites, gallery management,
activity logging, and system configuration.

Key Features:
- User registration and authentication
- Service catalog management
- Appointment scheduling (walk-in and home service)
- Customer favorites system
- Portfolio gallery
- Activity logging and audit trail
- System settings management
- Session and cache management

                              4. RELATIONSHIPS

4.1 PRIMARY RELATIONSHIPS
-------------------------

Users → Appointments (1:N)
- One user can have many appointments
- Each appointment belongs to one user
- Cascade delete: appointments deleted when user is deleted

Services → Appointments (1:N)
- One service can have many appointments
- Each appointment is for one service
- Cascade delete: appointments deleted when service is deleted

Users → Favorites (1:N)
- One user can favorite many services
- Each favorite belongs to one user
- Cascade delete: favorites deleted when user is deleted

Services → Favorites (1:N)
- One service can be favorited by many users
- Each favorite is for one service
- Cascade delete: favorites deleted when service is deleted

Users → Activity Logs (1:N)
- One user can have many activity logs
- Each log entry belongs to one user (optional)
- No cascade delete: logs preserved for audit

Users → Sessions (1:N)
- One user can have many sessions
- Each session belongs to one user (optional)
- No cascade delete: sessions managed by Laravel

Users → Password Reset Tokens (1:1)
- One user can have one reset token
- Each token belongs to one user
- Token expires after use

4.2 RELATIONSHIP CONSTRAINTS
